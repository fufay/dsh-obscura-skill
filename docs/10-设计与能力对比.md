# 10 · 设计与能力对比（vs dsh-lightpanda）

## 1. 结构

```
skill/dsh-obscura/
  SKILL.md                 触发词/决策表/用法
  assets/manifest.json     平台→归档→sha256（唯一真源）
  scripts/resolve.mjs      平台检测→下载→校验→解压→缓存
  scripts/fetch.mjs        P2 抓取（dump/eval/screenshot，多 URL + JSON）
  scripts/serve.mjs        P3 服务生命周期（storage 持久化、CJK 字体、代理）
  scripts/cdp.mjs          CDP：evaluate / 截图 / PDF / cookies / 等元素
```

- 与 lightpanda 同构（resolve/fetch/serve/cdp 四件套），便于替换与复用调用习惯。
- 差异：Obscura 的 CDP 必须走浏览器级 endpoint（`/devtools/browser` + `Target.attach(flatten)`），
  页面级 endpoint 会报 "No page for session"；`cdp.mjs` 已按此实现。

## 2. 能力对比

| 能力 | dsh-lightpanda | dsh-obscura | 说明 |
|---|---|---|---|
| 正文抽取 | markdown/html/structured_data/semantic_tree | markdown/html/text/links/**assets**/**cookies**/**original** | Obscura 多了子资源清单与 HttpOnly cookie 导出 |
| 截图 | 有（png） | 有（PNG，fetch 简版 + CDP 可控/全页） | Obscura 渲染更完整（Taffy 布局 + 文本整形） |
| PDF | 有（pdf） | 有（CDP `Page.printToPDF`，可设纸张/背景） | 已实测 `%PDF-1.4` |
| 登录态持久化 | `--cookie/--cookie-jar` | `serve --storage-dir`（cookie/localStorage 跨重启） | Obscura 更像浏览器 |
| Windows | ❌ 要 WSL2 | ✅ 原生 exe | 上游提供 |
| CDP | ✅（LP 专有方法） | ✅ 标准 Chrome 风格协议 | Puppeteer/Playwright 可接 |
| MCP | ❌ | ✅ `obscura mcp` | 可直接给 agent 用 |
| 并发抓取 | 批量 | `scrape --concurrency`（默认 10） | — |
| 体积（OHOS） | 74MB | 94MB（strip 后） | lightpanda 更轻 |
| 资源占用/速度 | 更轻更快（设计目标） | 更重（真渲染 + V8） | 按任务选型 |
| 强反爬 | 无 | **可选 stealth**（BoringSSL TLS 指纹 + GREASE + HTTP/2 + tracker 屏蔽） | 实测 JA3 与 render 不同；仍非万能 |

**结论**：功能面 Obscura 更宽（渲染、PDF、cookie 持久化、assets/HttpOnly、Windows 原生、MCP）；
lightpanda 在"轻量抓取、体积、启动成本"上仍占优。**默认路由**：轻抓取走 lightpanda，要渲染/登录态/Windows 走 obscura。

## 3. 关键设计取舍

1. **资产用归档而非单文件**：上游按 tar.gz/zip 发布，`resolve.mjs` 负责解压并定位 `obscura`/`obscura-worker`，
   避免为每个平台写死路径。
2. **OHOS 单独资产**：上游无 musl，直接复用会 `not found`（缺 glibc loader）；自建 + 自签后可直接执行。
3. **CJK 字体默认挂载**：`serve.mjs` 在 `process.platform === 'openharmony'` 时自动加 `--font-dir /system/fonts`；
   `fetch --screenshot` 没有该参数，所以 CJK 截图建议走 serve+CDP。
4. **缓存放 `$HOME`**：OHOS `/tmp` 不可执行（EPERM），默认 `~/.cache/dsh-obscura`，可用 `DSH_OBSCURA_CACHE` 覆盖。
5. **stealth 作为可选变体**：上游发 `-stealth` 资产；OHOS 自建也已跑通（BoringSSL 用 CMake+make+perl 构建，
   `BORING_BSSL_RUST_CPPLIB=c` 避免 `-lstdc++`，模板符号靠系统 `libc++_shared.so` 解析）。
   代价：包大 ~14MB、启动更慢、OHOS 二进制多一个系统库依赖。

## 4. 已知限制

- `fetch --screenshot` 无 CJK 字体参数（上游 CLI 限制）。
- 反爬（Cloudflare/Akamai）默认会挑战；实测走代理出口访问 example.com 也会被挑战。
- OHOS 资产需随本项目 release 发布；未发布前用 `DSH_OBSCURA_LOCAL_DIR` 离线安装。
- OHOS stealth 二进制依赖 `/system/lib64/libc++_shared.so`（系统自带；普通 OHOS PC 都有）。
