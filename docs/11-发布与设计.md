# 03 · 资产设计与发布流程

## 1. 资产模型

- 每个平台一个**归档**（tar.gz / zip），内含 `obscura` + `obscura-worker`（Windows 为 `.exe`）。
- **tag 跟随上游版本**：`v0.2.7`。同一 tag 下同时挂上游 5 个平台的 render 资产 + 本项目自建的 OHOS 资产。
- `skill/dsh-obscura/assets/manifest.json` 是唯一真源：平台 → 文件 → size/sha256 → 来源。
- `resolve.mjs` 下载后**按 sha256 校验**（归档哈希），解压到 `~/.cache/dsh-obscura/<tag>/<stem>/`，写 `.ok` 标记。
- 缓存命中判据：`.ok` 内容 == manifest sha256（避免"文件存在但被截断"）。

## 2. 首次/升级发布流程

```sh
# 1) 构建 OHOS 资产（首次会 clone 源码 + 下 V8 归档；约 3–8 分钟）
sh tools/build-obscura-ohos.sh
#    → _build/assets/obscura-aarch64-ohos.tar.gz（脚本末尾打印 size/sha256）

# 2) 刷新 manifest（上游 5 条 + OHOS 1 条）
node tools/update-manifest.mjs --fetch v0.2.7 --ohos _build/assets/obscura-aarch64-ohos.tar.gz
#    或离线：node tools/update-manifest.mjs --release-json rel.json --ohos ...

# 3) 发布（GitHub + AtomGit）
GH_REPO=fufay/dsh-obscura-skill AT_REPO=Kevin911/dsh-obscura-skill \
  sh tools/publish-release.sh --tag v0.2.7
```

验收：

```sh
rm -rf ~/.cache/dsh-obscura
node skill/dsh-obscura/scripts/resolve.mjs --check   # 选对资产
node skill/dsh-obscura/scripts/resolve.mjs           # 下载→sha256→解压
node skill/dsh-obscura/scripts/fetch.mjs https://example.com --dump markdown
node skill/dsh-obscura/scripts/serve.mjs ensure --port 9222
node skill/dsh-obscura/scripts/cdp.mjs --port 9222 --url https://example.com --screenshot /tmp/a.png
```

## 3. manifest 字段

| 字段 | 含义 |
|---|---|
| `release_tag` | 资产 tag（= 上游 tag） |
| `upstream.repo/tag/commit` | 来源与版本 |
| `assets[].os/arch/libc` | 平台键（`openharmony` 仅 aarch64） |
| `assets[].variant` | `render`（默认）；`stealth` 预留 |
| `assets[].file/size/sha256` | 归档与校验 |
| `assets[].source` | `upstream` / `self-built-ohos` |

## 4. 升级上游（Obscura 发新版）

1. 改 `build-obscura-ohos.sh` 里的 `REPO_TAG/REPO_COMMIT`（并确认新版本 `v8` 仍有 aarch64-musl 预编译）。
2. 跑 `node tools/update-manifest.mjs --fetch <newtag> ...`（会刷新 5 条上游资产）。
3. 重编 OHOS 资产、重发 release（AtomGit 不允许同名覆盖 → 用新 tag）。
4. 跑 §2 的验收；重点看 `resolve` 选中的 `file` 与 `cached`。

## 5. 已知限制

- OHOS 资产**不是**上游发布物：上游只发 glibc/macOS/Windows；本项目维护 musl 自签版。
- 构建依赖 `rusty_v8` 的 musl 预编译（v150.2.0 起提供）；升级前先确认新版本仍在发布。
- stealth（BoringSSL）未纳入资产；需要强反爬时另行构建 `-stealth` 变体。
